Alur: alat/simulator → POST /event → server → model Decision Tree menebak → diringkas per interval → GET /ringkasan → dashboard (polling tiap 3 detik).

Kenapa tidak jebol? Dashboard tidak pernah menerima data mentah. Server meringkas jadi 60 titik, dan grafik diperbarui dengan chart.update(), bukan dibuat ulang.

Interval ramai: z-score = (jumlah − rata-rata 30 interval sebelumnya) ÷ simpangan baku. Jika z > 3 dan jumlah ≥ 5, ditandai ramai.

Tebakan model memakai 4 ciri sinyal (kekuatan, durasi, waktu naik, jumlah pulsa). Cuaca tidak ikut menebak, hanya jadi pembanding.

Data masih simulasi. Istilah yang benar: "RF event kandidat". Bukan alat peringatan dini resmi dan tidak memprediksi hujan.
